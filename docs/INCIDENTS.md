# Инциденты

Самостоятельный раздел SimpleTracker: фронтенд `/incidents/`, API `/incidents`.
Инциденты не связаны с `tasks`, AZ, минорами, документами, часами, импортом Jira
и почтовой автоматизацией. Ссылка Jira — обычная HTTP(S)-ссылка, автоматического
опроса Jira нет. Список общий для авторизованных пользователей проекта.

## Хранение и API

Миграция `migrations/20261029_incidents.sql` добавляет таблицу `incidents`
в существующую PostgreSQL. Отдельная БД и новые переменные окружения не нужны.
Существующие таблицы и записи миграция не изменяет.

Поля: `number`, `jira_url`, `priority` (`low`, `medium`, `high`), `expires_at`,
`is_deferred`, `deferred_until`. Номер уникален без учёта регистра.
При отсрочке `deferred_until` обязателен и должен быть позже `expires_at`;
без отсрочки он равен `null`. Даты хранятся как `timestamptz`, API требует
явный часовой пояс. Ввод, таблица и календарь используют Europe/Moscow.
Календарь показывает `deferred_until` для отложенного инцидента и `expires_at`
для остальных; исходный срок всегда остаётся в таблице.

- `GET /incidents` возвращает `{ items: [...] }`, сортирует по действующему сроку.
- `POST /incidents` создаёт запись, возвращает её с HTTP 201.
- `PATCH /incidents/:id` принимает полный набор полей и текущую `version`.
- `DELETE /incidents/:id` принимает JSON `{ "version": 1 }`, возвращает HTTP 204.

Чтение требует обычную пользовательскую сессию. Запись доступна главному
администратору (`is_superadmin=true`), `editor` и `incident_editor`; `viewer`
только читает. Роль `incident_editor` не может изменять обычные задачи,
документы и теги. Внутренний токен бота и токены интеграций доступа не дают.
Неверные поля возвращают 400, отсутствие записи — 404, занятый номер
или устаревшая версия — 409. `version` предотвращает потерю параллельных правок.
Контракт доступен в `/openapi.json` и `/docs`.

## Выпуск

Push в `main` автоматически запускает production deploy. Перед push нужны
подтверждение владельца и свежая проверенная резервная копия.

1. На сервере `/srv/tasktracker` выполнить существующий
   `scripts/verify-v2-backup.sh`: копирование, восстановление во временную БД,
   сравнение количества строк и checksum. Если проверка не прошла — остановить выпуск.
2. Выпустить backend: workflow применит миграции инцидентов и
   `20261029_user_access_roles.sql` с `ON_ERROR_STOP=1`
   и отметит её в `schema_migrations`, затем пересоберёт только API.
3. Проверить `/health`, `/openapi.json`, отказ без сессии на `/incidents`
   и чтение списка с пользовательской сессией.
4. Выпустить frontend. `trailingSlash: true` создаёт
   `out/incidents/index.html`: существующий nginx `try_files $uri $uri/ /index.html`
   открывает страницу напрямую и после обновления. `/incidents` может перенаправляться
   nginx на `/incidents/`.
5. Проверить кнопку справа в панели вкладок, прямой адрес, ввод дат по Москве,
   создание/изменение/отсрочку на согласованных тестовых данных и обычный экран задач.
6. Через `POST /users` под главным администратором создать запрошенную учётную
   запись с `access_role=incident_editor`. Пароль передавать только в памяти
   процесса по HTTPS; не записывать в файлы, инструкции, журнал или аргументы команд.
   Существующую запись с тем же логином автоматически не перезаписывать.
7. Проверить вход поддержки: задачи/документы/часы читаются, изменение задач
   возвращает 403, создание/изменение/удаление инцидентов доступно.

## Роли доступа

`users.access_role` хранится отдельно от должности `role_text`.
Миграция сохраняет прежних наблюдателей как `viewer`, остальных как `editor`.
Флаг `is_superadmin` сохраняется и имеет приоритет над ролью доступа.
Менять `access_role` и создавать учётные записи может только главный администратор.
Смена роли увеличивает `session_generation`, старые сессии отзываются;
API дополнительно читает текущую роль из БД на каждом запросе.
Пользователь может изменить собственное имя и должность, но это не меняет права.
Главный администратор не может быть удалён или понижен через обычный API.
В настройках есть отдельный выбор прав и опциональные логин/пароль при создании.
Поддержка открывает карточку обычной задачи в режиме чтения, включая документы
и историю; управление пользователями и редактирование задач ей недоступны.

Бот, VPN, production `.env` и конфигурация nginx не требуют изменений.
Для отката интерфейса можно вернуть прежний release symlink; для API — прежний
проверенный исходник. Добавленную таблицу сохранить: откат кода не должен удалять
введённые инциденты. Удаление таблицы или данных требует отдельного подтверждения.

## Локальная проверка

`api/incidents.test.js` проверяет миграцию, HTTP CRUD, роли, валидацию,
уникальность номеров, конфликты версий, независимость от задач и OpenAPI на PGlite.
`api/permissions.test.js` проверяет реальные middleware авторизации и прав,
HTTP-маршруты пользователей и инцидентов, отзыв сессий и запрет повышения роли.
`api/tracker-fixture.mjs` добавляет синтетические инциденты только в локальную
временную БД; Dockerfile этот файл не копирует.
Тесты фронтенда `tests/incidents.test.mjs` проверяют границу московских суток,
перенос срока и календарь с високосными датами. Docker локально недоступен;
проверка production-контейнера выполняется при выпуске.
