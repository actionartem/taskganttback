# Выпуск статистики АЗ · 27.10.2026

## Изменение

В карточке вместо общего времени в этапах — окно статистики АЗ: ожидание
аналитика после замечаний, время в аналитике и ревью, ожидание заказчика,
задержка между отправкой документа и переходом АЗ в согласование в Jira.
Источники — отдельная дочерняя АЗ и фактические события почты.
График 10:00–19:00 МСК, полный день = 8 часов; неполный день пропорционально
8/9, без фиксированного обеда. Выходные/праздники и переносы РФ исключаются.
Проверенный календарь 2024–2027; вне покрытия неизвестные значения не подменяются.

Финальное подтверждённое согласование включает `automation_locked`.
Все автоматические записи (включая прежние маршруты) отклоняются при этом
флаге и в статусах оценки, готовности к разработке, разработки и завершения.
Ручные правки разрешены. Агент не может самостоятельно снять флаг.

## Схема и совместимость

Миграция `migrations/20261027_analysis_cycles.sql` в одной транзакции:

- `tasks.automation_locked boolean not null default false`;
- `tasks.automation_locked_at timestamptz`;
- `task_az` — отдельная привязка/снимок АЗ, родительский эпик, сопоставление статусов;
- `task_analysis_events` — факты писем и переходы АЗ, устойчивые внешние ID;
- индекс по задаче/времени события.

Миграция повторяема. Существующие задачи, документы и история не переписываются.
Старые данные эпика автоматически не преобразуются в историю АЗ.
Переменные окружения, ключи и настройки инфраструктуры не меняются.
Сборка API подхватывает новые `tracker-*.js` существующим Dockerfile.
Первые настоящие связи/циклы заполняет агент пользователя после сверки источников.

## Порядок production (после подтверждения новой миграции)

1. Сверить состояние `/srv/tasktracker`, HEAD и состав схемы.
2. Создать резервную копию существующим `scripts/verify-v2-backup.sh`:
   полностью восстановить в отдельной временной БД, сравнить контрольные
   количества строк. При расхождении/ошибке остановиться. Не удалять рабочую БД.
3. Проверить добавочную миграцию на восстановленной копии при необходимости;
   оригинал сохранён как `.verified.dump` с SHA-256.
4. Отправить backend в main: существующий workflow создаст ещё один dump,
   применит новую миграцию и пересоздаст только API. Бот остаётся выключенным.
5. Проверить Action, `/health`, OpenAPI 2.1.0, публичную инструкцию,
   наличие колонок/таблиц, сохранность количества задач и документы.
6. Отправить frontend в main, дождаться успешного Action, проверить новый release
   и интерфейс с `?v=<sha>`. Проверить авторизованный GET статистики и карточку
   без сохранений рабочих данных. Если агент ещё не заполнил факты, UI пустой.
7. Передать пользователю промпт со ссылкой `/integrations/guide` и правилом:
   сначала полная история и прежние циклы, финальное согласование последним.

Откат интерфейса — предыдущий release. Откат API — предыдущая версия кода;
добавленные колонки/таблицы можно сохранить, старая версия их игнорирует.
При откате API новое правило остановки автоматизации перестанет действовать:
сначала согласовать остановку внешнего агента. Не выполнять обратное удаление
таблиц и не восстанавливать поверх рабочей БД без отдельного разрешения.
